In this answer I will examine the points of discussion given from the perspective of the C# programming language. 

For C# the use of linters does not seem to be so popular as there is a built in IntelliSense support for the language in the Visual Studio products like Visual Studio Code that offers suggestions, and the language itself has a lot less leeway in how things can’t be formatted than untyped languages like JavaScript. The option to VSC seems to be using a more fully featured (paid) products like Rider or Resharper.  Likewise, C# seems to have built-in testing functionalities. For building C# .NET SDK is required. The SDK can be added to the CI workflow, on local machines C# builds can be done for example leveraging Visual Studio Code. Overall, the approach seems to be very different to JS/Node, as you rely a lot on the built-in functionalities of the .NET framework in C#, as opposed to patching together your preferred set of packages/functionalities like in JS/Node.

CI alternatives found on a quick Google search are for example: Google cloud build, GitLab CI/CD, Travis CI, CircleCI and Atlassian Bamboo.

Since it is always a hassle to use multiple services, I would use for cloud based the service where the code is hosted. GitHub Actions supports .NET projects so why not use that. Self-hosted vs cloud-based depends on the needs of the project. For bigger projects with lots of specific needs and configurability requirements self-hosted might be the only option, but for the ease of use and configuration I would use cloud based whenever possible for any smaller/simpler project.
